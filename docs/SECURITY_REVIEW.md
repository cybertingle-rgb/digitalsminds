# Security review (Phase 13, 2026-10-20)

Scope: authentication, authorization and data exposure, uploads and media, headers and XSS, secrets, SSRF,
dependencies. Every finding was traced through the code to a realistic attack before being accepted.

## Fixed

| Severity | Finding | Fix |
| --- | --- | --- |
| Medium | Open redirect for signed-in users: `/login?next=/%09/evil.com` passed the "same-site path" check, and browsers drop the tab, turning it into `//evil.com` | `safeNext` rejects control characters and backslashes and requires the URL to resolve to the same origin; unit and e2e tests |
| Low | Sign-in/sign-up/reset limits were per IP only; a misconfigured proxy would let an attacker rotate IPs | Extra per-account limits in the auth route: sign-in 50/hour per email (high enough that nobody can lock a real user out), sign-up, password-reset and verification emails 3/hour per email; e2e test |
| Low | Verification emails greeted the person with the name typed at sign-up, so someone could send scam text to any inbox through our mail server | Unverified accounts get a neutral greeting ("Hello,") |
| Low | `/api/auth/update-user` stored `googleEmail`, `phone`, `city`, `preferredLocale` and `name` without the app's format and length checks | The update hook applies the sign-up checks; invalid values are ignored |
| Low | Newsletter sign-up returned an error only for new addresses when email sending failed, revealing who is subscribed during a mail outage | Always answers "ok"; the pending link is dropped so the visitor can retry |
| Info | Account and subscriber deletion were gated by the export permissions | Separate `students.delete` and `newsletter.delete` permissions (Super Admin) |
| Low (found in Phase 12) | A password form submitted before JavaScript loaded used GET, putting the password in the URL | Password forms use `method="post"` |

## Accepted / to watch

- **Proxy IP trust** (`TRUSTED_PROXY_HOPS`, default 1): the client IP is taken from the right-most
  `X-Forwarded-For` entry added by Hostinger's proxy. If Hostinger support ever says requests pass through more
  than one proxy, set the variable accordingly. The per-account limits above cover the worst case.
- **In-memory limiters** (inquiries, newsletter, per-account auth limits) count per Node process. Fine for one
  instance; use a shared store if the app is ever scaled to several.
- **CSP allows inline scripts** (`'unsafe-inline'`), needed by Next.js without per-request nonces. No injection
  point was found: user text is always escaped, rich text never renders HTML, JSON-LD is escaped.
- **Certificate verification** has no rate limit; codes have about 8.5×10¹¹ combinations and a hit reveals only
  name, course and date (as stated in the Privacy Policy).

## Checked and found OK

- Every admin page, server action and API route checks permissions on the server; instructors are scoped to their
  own courses and uploads; students only ever see their own enrollments, progress, tickets, notifications and
  certificates; drafts are hidden from the public.
- No mass assignment: all writes go through strict schemas; sign-up and profile updates can never set role or
  status; suspended users have no sessions and cannot sign in.
- Uploads are checked by content (magic bytes), images re-encoded, SVG/HTML refused, macros refused, size-limited;
  storage keys are generated by the server and path traversal is blocked; private files require an approved
  enrollment and are served with `nosniff`, `attachment` and a sandbox CSP.
- Stored SMTP/Google secrets: AES-256-GCM, random IV, key derived from `BETTER_AUTH_SECRET` (HKDF).
- CSV exports neutralise spreadsheet formulas; exports and backups are Super Admin only and logged.
- No `child_process`, no fetching of user-supplied URLs; nodemailer file and URL access disabled.
- Only `.env.example` is in git.

## Dependencies

- `npm audit --omit=dev`: **0 vulnerabilities** in the packages the site runs on.
- `npm audit` (including development tools): 5 high, all from `braces` inside the lint tooling
  (`eslint-config-next` → `fast-glob` → `micromatch`). No patched version exists; it only parses this project's own
  lint patterns and never runs on the live site. Not fixed with `npm audit fix --force` (it would downgrade
  Next.js lint support).
- `better-auth` 1.7.7 already contains the fixes for the advisories published up to September 2026 (magic link and
  OAuth proxy issues; this site uses neither feature). Patch releases (1.7.8+) to be applied in routine maintenance
  with the full test suite.
